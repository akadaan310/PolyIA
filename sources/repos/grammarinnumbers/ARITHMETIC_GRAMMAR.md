# The Grammar of Arithmetic: +, −, ×, /

For each operation: input grammar, output grammar, admissibility, identity, composition, inverse, closure, machine implementation, cost, failure states, representation dependence. Proofs and evidence are cited from `RESULTS.md` and `EXPERIMENTS.md`.

## 2. Addition: 1 + 1 = 2, five ways

1. **Counting**: |{a}| + |{b}| = |{a, b}| for disjoint singletons.
2. **Successor**: add(1, S 0) = S(add(1, 0)) = S(1) = 2 — two rule applications.
3. **Cardinality**: + is the cardinality of a disjoint union; well defined because bijections compose.
4. **Algebra**: 1 + 1 is the element 2 of the ring generated by 1.
5. **Machine**: binary 1 + 1 = 10₂: the digit pair (1, 1) is a *generate* (G) in the carry monoid; the sum bit is 0 and the carry 1 moves one place left (GIN-DEF-041). In a half adder: sum = XOR(1, 1) = 0, carry = AND(1, 1) = 1.

*Invariant:* the value 2. *Generated:* a new position (the carry). *Merely represented:* the digit string `10` in base 2, `2` in base 10, `SS` in unary. 1 + 2 = 3, 2 + 2 = 4, 3 + 1 = 4, 4 + 1 = 5 behave the same way; in binary, 3 + 1 = 11₂ + 1₂ = 100₂ propagates a carry through two positions (one G, one P): the successor's worst case (GIN-PROP-010).

**Finite-width boundary.** In w-bit two's complement, MAX + 1 = MIN under wraparound, saturates, traps, or is undefined behaviour in C (GIN-EXP-012). Arbitrary precision moves the boundary to memory and time.

## 3. Subtraction: 0 − 1

Subtraction is the converse of addition: a − b = c ⇔ b + c = a. In ℕ, Sol(0, 1) = {c : 1 + c = 0} = ∅ — no solution. In ℤ it is {−1}. **What changed?** The *structure* was extended (ℕ → ℤ, the Grothendieck construction), which changed the admissible-result grammar; the *grammar of the operation* (converse of +) did not change. In ℤ/2ʷ (hardware) the answer is 2ʷ − 1: a quotient, not an extension — order is given up. Truncated subtraction 0 ∸ 1 = 0 totalizes without solving (GIN-PROP-016). As a machine operation, subtraction is a + ¬b + 1 in a ripple adder; the final carry is the *no-borrow* bit, i.e. the comparison a ≥ b (verified exhaustively, GIN-IMP-003).

## 4. Multiplication: 2 × 3 = 6

2 + 2 + 2 and 3 + 3 are different derivations with the same value; commutativity is a theorem (GIN-PROP-013). Multiplication is: repeated addition (primitive recursion), the cardinality of a Cartesian product, scaling, composition of scalings (x ↦ 2x then x ↦ 3x), shift-and-add in binary (partial products of an array multiplier: 64 gates for 4 × 4 bits, GIN-EXP-007), and a non-regular relation on numerals (GIN-THM-005). **Why 2 × 0 = 0 × 2 = 0 × 0 = 0:** four derivations in GIN-PROP-012 — ring axioms (needs cancellation), Peano recursion (base case plus induction), cardinality (∅ × A = ∅), empty sum.

## 5. Division: 6 / 3 = 2, 0 / 1 = 0, 1 / 0, 0 / 0

Division is the converse of multiplication: a / b = c ⇔ b · c = a. Six readings of 6/3 = 2: inverse multiplication (3 · 2 = 6); quotient and remainder (6 = 2·3 + 0); partition (6 objects into 3 equal groups of 2); repeated subtraction (6 − 3 − 3 = 0: two steps); ratio (6 : 3 = 2 : 1); field operation (6 · 3⁻¹). Machine readings: binary long division (110₂ ÷ 11₂ = 10₂, a restoring divider row by row), x86 `idiv`, AArch64 `sdiv`, RISC-V `divw` (GIN-OBS-007), Knuth's Algorithm D on limbs.

**The admissibility theorem (GIN-THM-001):** Sol(a, b) is ∅ or c₀ + Ann(b). Hence

| expression | equation | image condition a ∈ bR | kernel condition Ann(b) = 0 | outcome |
|---|---|---|---|---|
| 6 / 3 | 3c = 6 | ✓ | ✓ | 2 |
| 0 / 1 | 1c = 0 | ✓ (0 ∈ R) | ✓ (1 is a unit) | 0 |
| 1 / 0 | 0c = 1 | ✗ (0·R = {0}) | ✗ | **no solution** (image failure) |
| 0 / 0 | 0c = 0 | ✓ | ✗ (Ann(0) = R) | **non-unique** (kernel failure) |
| x / 0, x ≠ 0 | 0c = x | ✗ | ✗ | no solution |
| 0 / x, x ≠ 0 | xc = 0 | ✓ | ✓ | 0 |
| x / x, x ≠ 0 | xc = x | ✓ | ✓ | 1 |
| 7 / 2 in ℤ | 2c = 7 | ✗ (7 ∉ 2ℤ) | ✓ | no solution |
| 2 / 4 in ℤ/6 | 4c = 2 | ✓ (gcd 2 \| 2) | ✗ (Ann(4) = {0, 3}) | non-unique: {2, 5} |

**Symbolic vs numeric.** As rational functions x/x = 1; as an expression evaluated at x = 0 it is 0/0. Simplification must keep x ≠ 0 (GIN-PROP-014). **Limits** answer a different question: lim_{x→0} x/x = 1 is about a function near 0, not about the number 0/0.

**Machine floating point.** binary64: 1/0 = +∞ (divideByZero), 1/−0 = −∞, 0/0 = NaN (invalid). These are *special data*, not solutions: 0 × ∞ = NaN (GIN-PROP-015). **Exact rationals** (Python `fractions`, `ginsdk` domain Q) never round, and raise on zero divisors. **Algebraic x**: in ℚ(√2), division by nonzero elements is admissible (it is a field).

## 6. Extensions: what grammar changed?

`RESULTS.md` GIN-THM-004 (the trilemma table) and GIN-THM-006 (pairs): every system that gives 1/0 a value gives up ring laws (projective line, wheels, extended reals), the converse reading (IEEE, meadows, mathlib, AArch64, RISC-V), or 0 ≠ 1 (the zero ring); in the pair arithmetic all indeterminate forms (0/0, 0·∞, ∞ ± ∞, ∞/∞) evaluate to the single null pair that cannot be an element.
