# SNAD Implementation Plan

> **For agentic workers:** Use test-first implementation and isolated file ownership. The supplied mission explicitly requests end-to-end execution. Independent audit, corpus and laboratory tasks run concurrently; the coordinator integrates and verifies the result.

**Goal:** Deliver an executable, evidence-preserving SDK, complete corpus laboratory and continuation package.

**Architecture:** Dependency-free TypeScript core; adapter-specific data; static web UI; portable content-hashed mission artifacts. All services are optional transports.

**Tech Stack:** TypeScript, Node 24, Vite, Node test runner, fast-check, Playwright, axe.

**Spec:** docs/superpowers/specs/2026-10-18-snad-design.md and the supplied SNAD_CODEX_GODSEED.md.

## Global Constraints

- ISNAAD is strictly read-only; FALAK is unchanged and not a dependency.
- Complete domain is 6,236 ayahs across 114 surahs, including short verses.
- Source text is preserved; evidence and uncertainty survive serialization.
- No inferred speaker intent or visual resemblance is called a verified interpretation or theorem.
- The prior mission PURL is read-only. Persisted writes require readback.

## Review Focus

- Malformed and out-of-range loci must fail explicitly, never alias another verse.
- Missing grammatical features must produce valid unknown states and no fabricated annotations.
- Nested quotation and unresolved identity must survive roundtrip and perturbation.
- Duplicate unit identities, invalid spans and timestamps must not silently corrupt graph/provenance.
- Offline continuation must detect tampering and reference actual code and executable next steps.
