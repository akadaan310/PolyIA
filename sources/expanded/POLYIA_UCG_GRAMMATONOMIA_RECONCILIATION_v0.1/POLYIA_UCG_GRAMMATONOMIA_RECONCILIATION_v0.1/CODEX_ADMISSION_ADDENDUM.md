# Proposed Codex addendum — POLYIA scientific grammar admission (NOT EXECUTED)

**Scope:** When and only when the owner later authorizes integration work, append this to the existing POLYIA founding constitution as an ADDITIVE, versioned commission. Do not rewrite, replace or auto-execute the pre-existing UCG 156-section mission, Muse's GRAMMATONOMIA, or POLYIA's 96-clause constitution. Respect stronger governance restrictions in any of them.

## Supervisory machine

`PREFLIGHT → SOURCE_LOCK → BASELINE_REPLAY → RECONCILE_TYPES → ADMIT_GRAMMARS → GENERATE_MACHINES → COMPOSE → VERIFY → BENCHMARK → PROPOSE_RELEASE`

Nested child: UCG-HARNESS/0.2 for its scientific experiments. Outer POLYIA controls authority and release gates. `BLOCKED` is a legal terminal checkpoint for every stage, but never a PASS.

## Gate 0 — Source lock

Pin commit SHA and exact license for: POLYIA, UCG seed, Muse's actual runnable implementations (if supplied), Plicastratum, Relational Generativity, Division Infinity, Division Knot, PHONEX/WAZNOMIA, PILLAR9, CGT, GIN, ASTRO, HOMELESS. Record absent sources as missing; no invented replacements. Avoid network downloads without data-use review and human approval as required.

## Gate 1 — Reproduction and disputes

1. Reproduce supplied 17 UCG seed tests.
2. Remove hard-coded external atlas path from E03 by declaring a *versioned input path*, not by substituting invented data. Re-run E01..E05 with correct licensed source, retain old failures.
3. Report E02 precision/recall with the bundled 48-item curated subset distinguished from full QM9/G4MP2.
4. Resolve whether RDKit is a generator dependency, normalization backend or independent witness. Enforce selected boundary automatically.
5. Obtain Muse's Wave-1 implementation and run tests; until then mark claims NOT_RUN.
6. Preserve source-derived claims as claims; do not interpret assertion logs as independent empirical confirmation.

## Gate 2 — Unified but non-destructive vocabulary

Introduce `PIC/0.2` proposed canonical interchange card covering typed alphabet, grammar and negative grammar, denotation, machine kind, relation ports, effects/permissions, evidence state, reversibility/loss, cost, hashes and replay. Provide adapters FROM UCG `GUC`, Muse `L_v`, Plicastratum `plicate/applicata`, Relational Generativity `K`, Division Knot/Infinity EFC. Preserve original records and add adapter round-trip proof for every information field claimed to survive.

## Gate 3 — Compiler genesis

Build real compiler paths `grammar card -> recognizer/generator/transducer/rewrite+guard machine -> native typed IR -> executable reference`, not JSON interpretation. Validate interpreter/compiled equivalence for a bounded sample and record every non-commuting transformation. Generated source code without executed result is NOT a certified capability.

## Gate 4 — Two independent implementations + one composition

(A) Language case: attested English `topology` → source/IPA variants → scoped language pack candidates → Arabic/Greek morphology branches → evidence-ranked graph with no fabricated etymology. (B) Non-linguistic case: IUPAC name ↔ small organic structural graph, checked for syntax, canonicality, valence scope and inverse ambiguity. (C) Composition: a single POLYIA concierge must assemble (A) and (B) under common PIC/0.2 ports; refuse untyped bridge between them. Both source→program→state trace and executable output→verifier→receipt required.

## Gate 5 — Generative essay experiment (hypothesis, not mandatory for first candidate)

Using sourced mini-corpora, generate a 3-domain comparison (stem cell biology, adult-content social topic, corn agriculture) in English. Planner must return both admissible comparisons and explicit non-relations; citation identifiers and source hashes stay attached. Grammar constraints may draw abstract operator patterns from Muse's varieties, but English surface grammar remains authoritative for English grammaticality. Optional tiny language model may propose connectors or style candidates only; never fabricate domain facts or override refusal.

## Gate 6 — Novelty and performance

Benchmark each unit against correct domain-specific baselines (OpenFST for finite-state morphology/phonology, a standard parser, RDKit/OPSIN for chemical naming, SymPy for calculus, standard dependency/index search for performance). Track build time, execution time, peak memory, cache and corpus size, precision/recall, wrong admissions, proofs and failed validations. Novelty is a falsifiable hypothesis until independently evaluated.

## Gate 7 — Final ownership and release

No push, remote mutation, Oracle VM setup, deployment, paid dataset use, cloud service operation or source repository mutation in this reconnaissance. Only prepare signed-off execution plan and an inventory of artifacts for the owner. If the owner later authorizes an actual run, use a separate temporary worktree, human-readable plan, pinned inputs and a verified outer harness.

## Mandatory acceptance receipts

`SOURCE_LOCKED`, `REPLAY_PASS` or `REPLAY_BLOCKED`, `PIC_ROUNDTRIP`, `MACHINE_EXECUTED`, `CHECKER_WITNESSED`, `CROSS_DOMAIN_COMPOSITION`, `NEGATIVE_CASE_REFUSED`, `PERFORMANCE_BASELINED`, `OWNER_RELEASE_PENDING`.

Each receipt carries actual commands, source SHA-256, stdout/stderr hashes, artifact hashes, test counts, failures and scope. A receipt with just an attractive label is not evidence.
