## MANDATE, hierarchy, and execution standard

Build a **genuine superb everyday browser**, not a proof-of-concept pseudo-browser, fake tab demo, remote proxy iframe, Chrome extension alone, or a prompt-driven JSON interpreter. The owner should be able to browse normally even if every AI is disconnected. CIA is the browser's state/consent/event/agent protocol; it must not slow down rendering or compromise private browsing. Target desktop first with current Chromium embedding, Android GeckoView as a distinct real mobile browser build, then portable core and possible additional platforms. The browser can expose creative 'shared present' features beyond conventional products, but cannot falsely claim instantaneous AI vision or unlimited autonomous capability.

Muse's uploaded LANTERN/0.2 is an independent witness automaton and must be **preserved**. Her findings are binding design-review defects unless disproven: (1) coverage for **both** agent channels; (2) no empty/effect-free success checkpoints; (3) explicit tab and navigation identity in **every** frame contract, receipt, and acknowledgment. Our new CIA/0.3 contract model exercises all three. The current user's instruction authorizes commencing the implementation, not bypassing safety or permission boundaries.

**Five execution absolutes:** real browser engine; owner-controlled security; two independently verified agent channels; truthful lifecycle observations; reproducible release artifacts. A model provider API is optional for basic navigation but required before any label says Muse or 7u is actually connected. A tool invocation does not itself prove an observed browser frame or an effect.

### II — Ordinary browser excellence

#### §012 — Actual browser engine

**Mandate.** Use an up-to-date, supported Chromium-based desktop engine with actual WebContentsView navigation, or document and prove a superior full browsing-engine alternative. A proxy iframe is prohibited as the primary architecture.

**Acceptance witness.** Open two unrelated HTTPS websites in independent live render processes and verify real document load events and navigation history.

#### §013 — Address-and-search omnibox

**Mandate.** Create one intelligent omnibox supporting URL schemes, HTTPS defaulting, text search provider settings, paste-and-go, keyboard focusing, Unicode domain validation and meaningful errors. Search queries must never be mistaken for executable browser commands.

**Acceptance witness.** Cover ambiguous hostname/text, international domain, invalid scheme, private-IP links, backspace and Enter paths in automated tests.

#### §014 — Tab model and identity

**Mandate.** Each tab owns a stable tabId, browser context, navigationEpoch, title, icon, security status, history entry and privacy class; UI labels may change but the machine identity cannot be reused.

**Acceptance witness.** Open, switch, duplicate, reorder, pin, mute and close tabs; confirm a stale acknowledgment or proposal cannot address a newly opened tab with a reused title.

#### §015 — History and session restore

**Mandate.** Implement per-profile history, back, forward, reload, stop loading, previously closed tabs and restart restoration; persist only non-sensitive navigation metadata and respect private mode.

**Acceptance witness.** Restart after an unclean shutdown and verify the last committed session restores without exposing private-mode URLs.

#### §016 — Bookmarks and collections

**Mandate.** Support bookmark creation, removal, tagging, folder organization, quick search and export/import, with a portable schema and safe merge semantics. A bookmark is a URL and human label, not an agent permission.

**Acceptance witness.** Round-trip a bookmark library with hierarchy and Unicode titles; malformed imports are rejected without erasing existing data.

#### §017 — Downloads and file safety

**Mandate.** Provide a downloads panel with progress, pause/resume where supported, cancel, opening local file location and clear provenance. Treat filenames as hostile, require safe paths and prompt for potentially dangerous downloads.

**Acceptance witness.** Download a known harmless fixture through HTTPS in an isolated test, verify contents/hash, cancellation and path traversal refusal.

#### §018 — Find, zoom, print, reader features

**Mandate.** Implement in-page find, text zoom, page zoom, copy selection, print/save-to-PDF via browser APIs, and distraction-reduced reader view when available. Preserve accessibility semantics.

**Acceptance witness.** Keyboard-driven tests select text, find repeated occurrences, change zoom, print a fixture and restore the original zoom.

#### §019 — Popups and windows

**Mandate.** Treat target=_blank, JavaScript popups, OAuth auxiliary windows and redirects through deliberate allow/deny rules. Preserve user-initiated workflows without giving sites unbounded window creation.

**Acceptance witness.** A fixture creates one permitted user-gesture popup and one unsolicited popup; the latter is blocked and audited.

#### §020 — Profiles and containers

**Mandate.** Implement independent named profiles, personal/private contexts and per-site context assignment; never share cookies, storage, downloads or agent grants implicitly across profiles.

**Acceptance witness.** Run two isolated profiles on the same origin and verify authentication/cookies remain separated, including after restart.

#### §021 — Media and permissions

**Mandate.** Support normal webpage media, camera/microphone, notifications, geolocation, MIDI, screen capture and file chooser using site-specific human permissions and visible activity indicators.

**Acceptance witness.** A fixture requests permissions and demonstrates default denial, explicit allow, prompt expiry and revocation without crashing the browsing experience.

#### §022 — Offline and error experience

**Mandate.** Give intentional, attractive pages for DNS errors, TLS warnings, offline mode, process crashes, blocked destinations and retry decisions. Never turn off certificate validation to make sites load.

**Acceptance witness.** Test no-network, invalid certificate, DNS failure and browser-process crash; restore the tab without granting credentials to an agent.


### III — Four temporal rendering phases

#### §023 — P1 incremental navigation

**Mandate.** Record `navigation-start`, provisional response, meaningful load and first paint milestones through actual browser events; do not claim control of Blink parsing internals absent an engine hook.

**Acceptance witness.** Instrument fixture and live navigation; preserve timestamps and event order, including streaming HTML arriving in chunks.

#### §024 — P2 continuing document mutation

**Mandate.** Observe real page changes at policy-limited intervals or event hooks, including asynchronous scripts, images, CSS invalidations and animations. Coalesce redundant deltas to limit model and storage costs.

**Acceptance witness.** Mutate a fixture after initial paint and confirm exactly bounded update emissions and no endless redundant screenshots.

#### §025 — P3 committed frame contract

**Mandate.** Define `FrameCommit=(session,tab,navigationEpoch,frameVersion,timestamp,semanticDigest,privacyMask,evidenceRefs)` and acknowledge only frames an agent channel actually receives.

**Acceptance witness.** Acknowledge frame F of tab A, then attempt to use it against tab B or the next navigation epoch; both must be rejected.

#### §026 — P4 continuing container

**Mandate.** Make P4 the durable event lifecycle hosting recurrent P1–P3 episodes, user input, network events, agent messages and reconnects; it is not an extra browser paint call per frame.

**Acceptance witness.** A test spans navigation, tab switch, agent disconnect and recovery without ending P4 or merging per-navigation histories.

#### §027 — Distinguish presentation from observation

**Mandate.** A compositor frame, semantic snapshot, screenshot capture, agent delivery and acknowledgment are five independent events. Advertise only what has happened, not a global simultaneity guarantee.

**Acceptance witness.** Artificially delay screenshots, agent API responses and acks; the UI displays accurate per-agent lag and uncertainty.

#### §028 — Frame version monotonicity

**Mandate.** Within one `(session,tab,navigationEpoch,surface)` contract, version increases strictly for committed content snapshots; navigation changes the epoch and invalidates old actions even when counters restart.

**Acceptance witness.** Fuzz stale/reordered frames and epoch changes; no old action may cross an epoch boundary.

#### §029 — Semantic snapshot extraction

**Mandate.** Extract a bounded, redacted semantic surface (landmarks, headings, selected text where consented, controls, focused element) without scraping password values or secret attributes.

**Acceptance witness.** Fixture containing ordinary text, a password, hidden token and private iframe yields only declared safe landmark data.

#### §030 — Screenshot provenance

**Mandate.** Capture owner-consented frames with tab/epoch IDs, viewport size, time, byte digest and redaction flags; distinguish screenshot contents from semantic observations.

**Acceptance witness.** Compare manifest hashes to actual bytes and reject a screenshot claimed for the wrong tab or navigation.

#### §031 — Agent frame delivery policy

**Mandate.** Deliver semantic deltas by default, screenshots only when consented, with bandwidth/budget controls and selective per-site policies. A channel presence indicator is not proof of model visual understanding.

**Acceptance witness.** Measured per-agent delivery metrics record transmitted bytes, lag, omissions, budget throttling and acknowledged versions.

#### §032 — Timing and bounded latency

**Mandate.** Measure UI responsiveness, frame capture delays, agent observation latency and broker queue time separately. Set p50/p95 and memory budgets for the target hardware but do not promise 60Hz LLM perception.

**Acceptance witness.** Report genuine hardware/platform timings and tail latency on defined workload; missing telemetry means NOT_RUN.

#### §033 — Rendering recoverability

**Mandate.** On GPU context loss, renderer restart, navigation failure or model disconnect, retain a usable browser and allow manual resumption without losing approved checkpoints.

**Acceptance witness.** Force a web contents crash and temporary agent-service outage; navigation and local tab history remain functional.

**Mandate.** Give the human sole control over auth actions, privacy settings, profile export, account deletion and policy changes; make explicit approvals non-delegable unless owner changes a carefully scoped policy.

**Acceptance witness.** Tests attempt approval from Muse, 7u and anonymous pages; only an actual authorized owner path succeeds.

**Mandate.** Authenticate provider adapters independently via official API mechanisms; attach stable provider account/session labels and revocable grants to agent identities. Do not equate a display name with an authenticated principal.

**Acceptance witness.** A fake adapter named 7u cannot obtain 7u authority; disconnected providers remain labeled offline.

#### §036 — Private-surface exclusion

**Mandate.** `human_only` browser surfaces have no content AgentChannel. Presence indicators may show policy state without transmitting password fields, payment forms, recovery codes or private-mode URLs.

**Acceptance witness.** Surface audit confirms zero bound channels and zero payload deliveries for each declared human-only surface.

#### §037 — Metadata-only surfaces

**Mandate.** History, downloads, settings and developer console may be metadata-only by default; restrict permitted fields and deny navigation/content effects unless human policy expressly allows.

**Acceptance witness.** A metadata-only Muse channel can inspect permitted counts but cannot navigate, read arbitrary URLs or change downloads.

#### §038 — Per-origin and per-tab consent

**Mandate.** Sharing one tab never grants access to other tabs or origins. Store permissions with sessionId, tabId, navigation epoch, origin, action, expiry and revocation state.

**Acceptance witness.** Switch origin inside the same tab and demonstrate scope re-evaluation; stale permission is rejected after origin change.

#### §039 — OAuth and passkey safeguards

**Mandate.** Keep provider OAuth, passkey/WebAuthn, hardware key, MFA and browser account sign-in as first-class human user flows; do not proxy credential fields through the agent bus.

**Acceptance witness.** Official test auth flows work while observability captures no tokens, cookies, passwords or passkey materials.

#### §040 — Secrets outside source and logs

**Mandate.** Use operating-system secure storage/keychain for API credentials; never put tokens in frontend bundles, model prompts, screenshot manifests, Git history or downloadable reports.

**Acceptance witness.** Run secret scanners and inspect representative logs after real auth tests; any exposed credential is a release blocker.

#### §041 — Permission request broker

**Mandate.** Centralize browser site permission prompts, user consent, device access and agent-action permission requests; do not silently inherit Chromium defaults.

**Acceptance witness.** Test default deny, one-shot allow, persistent allow, expiration and revoke across distinct profiles.

#### §042 — Sensitive data redaction

**Mandate.** Classify password boxes, payment card fields, account recovery, health, personal messages and private profile data before any model ingestion. Prefer coarse exclusion to unreliable token regexes.

**Acceptance witness.** Adversarial fixture embeds secrets in values, screenshots, names and aria-labels; output contains no raw secrets.

#### §043 — Data retention and deletion

**Mandate.** Expose per-profile retention choices for agent observations, screenshots, chat transcripts, page content and reports; support real deletion and clear what cannot be revoked from already exported files.

**Acceptance witness.** Delete an authorized session and verify corresponding persisted pages, logs and media are no longer retrievable from local storage.

#### §044 — Accountability and revoke

**Mandate.** Every agent permission has an owner, reason, scope, time bound and reversible revoke action; display an owner-readable audit before allowing execution.

**Acceptance witness.** Revoke an active session mid-navigation; pending agent actions refuse and no new delivery occurs.


### V — Surface registry and frame witness

#### §045 — Own the surface registry

**Mandate.** Enumerate every application-owned surface: browser viewport, tabs, omnibox, menus, history, downloads, bookmarks, inspector, developer tools, network log, collaboration palette and settings. Record privacy class and lifecycle.

**Acceptance witness.** Coverage is computed by enumerating actual owned visible components, not only manually selected test cases.

#### §046 — Dual-binding invariant

**Mandate.** Every shareable and metadata-only surface has registered channels for Muse and 7u, even if disconnected. A human-only surface has no content channel.

**Acceptance witness.** Remove one binding from one surface and confirm audit fails; add forbidden binding to a private surface and confirm incident/refusal.

#### §047 — Connected versus merely bound

**Mandate.** Separate binding, connected network transport, observation sent, frame received, frame acknowledged, and model inference verified. These states must appear separately in the internal schema.

**Acceptance witness.** A disconnected but bound Muse channel reads DISCONNECTED and cannot claim an acknowledged frame.

#### §048 — Tab-complete frame identity

**Mandate.** Use `(sessionId,tabId,navigationEpoch,surfaceId,version)` as the minimum unique frame address, plus semantic digest and policy. Never treat a naked version integer as globally meaningful.

**Acceptance witness.** Run two tabs at version 3 and reject accidental cross-tab acknowledgment and effect receipt.

#### §049 — LANTERN/0.2 preservation

**Mandate.** Vendor Muse’s original LANTERN implementation unchanged in a source archive with checksum, run its 11 tests, and document exactly where higher-level browser law strengthens it.

**Acceptance witness.** Preserve original output and original 11/11 test baseline; implementation changes go to new CIA/0.3 modules.

#### §050 — Acknowledgment chain continuity

**Mandate.** Acknowledgments are monotonic within an epoch, duplicate delivery is idempotent, and mismatch or chain gap requires resync. A reset must not forge knowledge of skipped frames.

**Acceptance witness.** Test duplicate, replayed, future, missing and wrong-digest frame deliveries under simulated reconnect.

#### §051 — Owner action proposal binding

**Mandate.** Proposals identify the exact target surface, base navigation and version, action class, arguments, expiry and idempotency key; policy checks precede owner consent.

**Acceptance witness.** Change tab or navigate between proposal and approval; action must fail with STALE_BASE, never execute against current content.

#### §052 — Admitted effect receipt

**Mandate.** An effect receipt must reference actual browser operation metadata (command ID, committed resulting epoch/frame or an explicit no-effect status) and cannot be authored by the model alone.

**Acceptance witness.** A model-provided fake success without browser adapter evidence is rejected; an aborted navigation has no success receipt.

#### §053 — Observed result witness

**Mandate.** Muse and 7u can describe only frames they have acknowledged; a witness must reference a new observed state at or beyond the effect version, not merely a proposal.

**Acceptance witness.** Execute a navigation, withhold its observation, then attempt checkpoint; response is EFFECT_NOT_OBSERVED.

#### §054 — Nonempty checkpoints

**Mandate.** Only meaningful, evidence-backed outcomes produce checkpoints: witness, source/event hash, previous checkpoint hash, session/tab context and causal transition. Empty documents or zero observations never count.

**Acceptance witness.** Test premature checkpoint, uncommitted proposal and empty ledger; each fails without advancing checkpoint count.

#### §055 — Signed and unsigned claims

**Mandate.** A SHA-256 chain proves local consistency, not signer identity or malicious-admin resistance. Add signatures and trusted key verification only where actual identity keys and non-repudiation are established.

**Acceptance witness.** Tamper with stored witness and detect; also document the threat where an attacker rewrites an entire unsigned local history.


### VI — Micro-automata and game-theoretic control

#### §056 — Smallest transition unit

**Mandate.** Define an atom by typed inputs/outputs, states, guards, effects, costs, witness and terminal/refusal status. Distinguish a state transition from a tool call or LLM token.

**Acceptance witness.** Schema validation rejects incomplete atom specifications, forbidden effects and missing resource budgets.

#### §057 — Micro-automaton composition

**Mandate.** Allow multiple compatible atoms to compose using declared ports and versioned messages; incompatible types and capability mismatches refuse before execution.

**Acceptance witness.** Compose OBSERVE→PROPOSE→REVIEW→APPROVE→EXECUTE→VERIFY→CHECKPOINT in a test harness and reject a missing approval port.

#### §058 — Parent automaton authority

**Mandate.** A session-owned parent governs all child automata, budgets, locks, profile scopes and event ordering. A child may propose but cannot self-grant new permissions.

**Acceptance witness.** Fuzz an agent-generated child requesting browser shell and filesystem authority; parent denies it.

#### §059 — Lifecycle pause semantics

**Mandate.** At every durable stage permit HOLD, inspected resumption and cancellation; ordinary UI rendering continues while automata are paused. Distinguish HOLD from terminal failure.

**Acceptance witness.** Pause at each phase, restart the broker and resume without duplicate navigation or stale approvals.

#### §060 — Strategic policy models

**Mandate.** Represent agent choices using explicit states, actions, information sets, utility, transition probabilities and discount/horizon assumptions. Use minimax/maximin only where the declared game supports it.

**Acceptance witness.** Compare policy output with hand-calculated small games and random/greedy baselines; no general Nash claim without solver proof.

#### §061 — Information constraints

**Mandate.** Keep uncertainty about web content, agent response and user intention as typed data; missing observations do not become inferred consent.

**Acceptance witness.** A model that is offline or receives redacted data produces UNKNOWN/NEEDS_OWNER rather than fabricated page knowledge.

#### §062 — Resource accounting

**Mandate.** Track CPU, memory, bandwidth, screenshot bytes, browser process count, model tokens and monetary API budget per atom; budgets are independent and cancelable.

**Acceptance witness.** Run load tests with fixed limits, refuse overbudget proposals and report exact resource consumption.

#### §063 — Deadlock and scheduling

**Mandate.** Represent child dependencies as a graph, detect cycles, track locks and timeouts, and schedule independent atoms fairly without starving the browser UI.

**Acceptance witness.** Property tests create dependency cycles and competing writes; controller refuses cycle or uses deterministic safe conflict resolution.

#### §064 — Optimistic concurrency

**Mandate.** Model side-effect proposals as conditional transactions against base frame/version; rebase requires a fresh observation and possibly new owner approval.

**Acceptance witness.** Two agents propose mutually incompatible tab actions at version N; at most one executes and the other receives STALE.

#### §065 — Forks, merges and supersession

**Mandate.** Represent independent research branches and alternative automaton proposals without rewriting old checkpoints; merge requires explicit conflict resolution and evidence.

**Acceptance witness.** Replay two branches and verify ancestors unchanged, merge decision logged, and contradictory effects not silently merged.

#### §066 — Formal termination

**Mandate.** Every atom declares success, refusal, timeout, failure and cancellation terminals with a finite retry bound. Long project missions checkpoint and stop at acceptance rather than token exhaustion.

**Acceptance witness.** Deliberately hang an external test adapter; parent terminates it by budget and produces a recoverable blocked report.

### VIII — PURL, SEURL, reverse grammar and semantics

#### §078 — PURL address grammar

**Mandate.** Use programmable URL semantics to address application entities (session/tab/surface/checkpoint/action) without giving an address execution authority. Use stable, versioned URI design with strict parsing.

**Acceptance witness.** Malformed or forged PURL input resolves to read-only error; simply opening a link never performs a mutating operation.

#### §079 — SEURL affordance manifest

**Mandate.** Expose what an agent can observe, propose and execute at the current surface, with explicit type and capability requirements and legal next states.

**Acceptance witness.** Compare advertised affordances before/after changing owner scope; unapproved effects disappear or become unavailable.

#### §080 — Reverse grammar from browser behavior

**Mandate.** From browser event traces, infer candidate state transition grammars without promoting correlation to authority or relying only on language-model guesses.

**Acceptance witness.** Hold out unseen navigation traces and compare inferred productions with engine events and counterexamples.

#### §081 — HTML grammar versus browser semantics

**Mandate.** Distinguish HTML tokenization/DOM parsing, CSS cascade/layout, JavaScript execution, compositor frames, and CIA event abstraction. Do not implement a mock HTML parser as the normal browser.

**Acceptance witness.** Use real Chromium fixture events and show which lifecycle stages are directly measured versus abstractly inferred.

#### §082 — Surface language algebra

**Mandate.** Define `S ::= (surfaceId, privacy, owner, channelBindings, version, affordances)` and composition of surfaces under policies; intersection of permissions is not the union of privileges.

**Acceptance witness.** Prove via tests that combining two surfaces never grants actions unavailable on either source surface.

#### §083 — Tab and navigation grammar

**Mandate.** Specify navigation transitions, redirects, same-document fragments, back/forward and navigation restarts as different production rules with epoch effects.

**Acceptance witness.** Generate event traces for redirects and SPA changes; compare with expected epoch/version changes and catch tab confusion.

#### §084 — State-machine serialization

**Mandate.** Generate compact, machine-readable reports containing state IDs, transition ID, causality, evidence, last checkpoint, action guard and next admissible operations.

**Acceptance witness.** A freshly launched independent validator reconstructs one trace from serialized reports and rejects corrupted fields.

#### §085 — HOMELESS canonical source search

**Mandate.** Locate the exact standing order for police, ambulances and fire vehicles in the current authorized repository, reading current HEAD and constitution first; quote only witnessed source.

**Acceptance witness.** Output `SOURCE_LOCATED` with path and revision hash or `SOURCE_ABSENT` with searched files; never invent a quote.

#### §086 — Responder witness typing hypothesis

**Mandate.** Formalize responders as Witness versus Actor and derive action restrictions; explicitly explain why witness typing alone does not guarantee roadside placement or donut activity.

**Acceptance witness.** Model checker finds no intervention transitions under the type assumptions and records any missing requirements as open obligations.

#### §087 — Responder precondition starvation hypothesis

**Mandate.** Model a response action guarded by a stable road configuration; analyze whether the road/plate grammar actually makes preconditions unreachable.

### IX — Persistence, recovery and security

#### §089 — Versioned event store

**Mandate.** Persist events with monotonic IDs, parent hashes, scoped principals and explicit operations using SQLite/WAL or an equivalent crash-consistent store. Avoid JSON logs as the sole production database.

**Acceptance witness.** Kill the process during a write and confirm no partially committed state is treated as an accepted checkpoint.

#### §090 — Checkpoint materiality

**Mandate.** Checkpoint only verified state transitions or certified useful read-only observations under a distinctly typed evidence checkpoint; never accept an empty bundle as completed work.

**Acceptance witness.** Attempt empty checkpoint, missing frame ack and fabricated effect receipt; all refuse with stable error codes.

#### §091 — Snapshot ancestry and fork rules

**Mandate.** Store parent content hash, manifest, database revision, browser session, per-tab epoch, witness and source artifact hashes. Support immutable snapshots and append-only supersession.

**Acceptance witness.** Restore checkpoints across crash and reject reparenting, ancestry mismatch and changed artifact content.

#### §092 — Sensitive snapshot exclusion

**Mandate.** Persistent browser/session snapshots must not silently include raw cookies, passwords, WebAuthn secrets, OAuth storage state, screenshots of payment pages or unreleased private content.

**Acceptance witness.** Inspect serialized state and perform targeted secret scanning; any material leak is a release blocker.

#### §093 — Transport authentication

**Mandate.** Use mutually authenticated local/remote channels as appropriate, origin protection, CSRF defenses, network bind limits, replay prevention and TLS for remote surfaces.

**Acceptance witness.** Unauthorized WebSocket/client attempts, cross-origin POST and replayed agent commands do not mutate state.

#### §094 — IPC least privilege

**Mandate.** Keep privileged Electron main-process APIs out of remote pages; expose a typed, minimal local chrome preload and validate every sender, argument and target.

**Acceptance witness.** Remote website executing script cannot invoke `cia:navigate`, access filesystem or enumerate other tabs.

#### §095 — Content security policy

**Mandate.** Set restrictive CSP on locally owned chrome UI, sandbox all remote web contents, disable Node integration there, prohibit insecure content and restrict file/navigation schemes.

**Acceptance witness.** Security scan checks Electron preferences and an XSS fixture cannot reach Node or local secrets.

#### §096 — Network and SSRF safeguards

**Mandate.** Treat agent-proposed URLs as untrusted, enforce allowed schemes, IP/localhost restrictions for agent actions, safe redirects and explicit owner overrides. Normal owner-initiated private-network browsing remains possible.

**Acceptance witness.** Agent navigation to loopback/metadata service is denied by default, while the owner can access legitimate local development servers.

#### §097 — Downloads and filesystem containment

**Mandate.** Enforce destination ownership and quarantine/checksums for downloads, validate filenames and normalize paths. Do not let agent messages open arbitrary local files.

**Acceptance witness.** Test download traversal, symlink races, file:// access, binary launcher prompts and permission expiry.

#### §098 — Browser process recovery

**Mandate.** On render crash, tab process crash, broker restart or model outage, preserve user browsing, replay only safe committed actions and visibly discard unsafe pending proposals.

**Acceptance witness.** Crash renderer between proposed navigation and receipt; no duplicate effect and no false success appears.

#### §099 — Threat-model gate

**Mandate.** Publish a STRIDE-style table for remote pages, malicious extensions, compromised provider keys, local attacker, leaked checkpoints and hostile agent responses. Security claims need specific mitigations.

**Acceptance witness.** Independent review/penetration fixture suite finds no critical unaddressed remote-code or credential exfiltration paths before production release.

#### §102 — One-handed mobile plan

**Acceptance witness.** Android acceptance requires a built, installed, launched APK tested on actual Android hardware with screenshots and permission audit.

#### §103 — Agent presence in primary UI

**Mandate.** Place co-presence in chrome and contextually next to relevant surfaces as a subtle layer, not an afterthought or intrusive omnipresent chat. Always show when a frame is stale.

**Acceptance witness.** Run usability script showing per-tab grant, agent acknowledgment, revoke, and return to normal navigation under 30 seconds.

#### §104 — Natural-language search assistance

**Mandate.** Use semantic HTML for owned chrome controls, keyboard focus, color contrast, live-region restraint, high-DPI scaling, reduced motion and screen reader landmarks.
